---
title: "Live market"
description: "A REST snapshot of the cheapest current listings, plus a WebSocket that tells you when the listings you show sell or reprice."
---

The live market is the set of cheapest current listings across connected
marketplaces, kept warm and repriced for the viewer. It has two surfaces:

- `GET /market` — a snapshot of the feed, cheapest first.
- `GET /market/live` — a WebSocket that reports, in real time, when the
  listings you show sell or change price.

Use them together: render from the snapshot, then watch the listings on
screen so a sold one disappears before the user tries to buy it. Prices on
both surfaces already include the viewer's fee, so you render them as-is.

## Snapshot

`GET /market` returns the curated feed sorted cheapest first.

```ts
const { items, total } = await api<{ items: MarketListing[]; total: number }>(
  "/market?limit=100",
  { method: "GET" },
  "user_42",
);
```

<ParamField query="page" type="integer" default="1">
  1-based page number.
</ParamField>

<ParamField query="limit" type="integer" default="100">
  Listings per page, 1–500, or `-1` to return the whole feed in one response.
</ParamField>

Each entry's `price` is a decimal number with the viewer's fee already
applied, and `id` is the buyable listing id you pass to the trade
endpoints. See [Data models](/reference/data-models) for the full
`MarketListing` shape.

## Live stream

```http
wss://api.skinshark.gg/market/live?scope=watch
```

The socket tells you, within seconds, when a listing you care about sells,
disappears or changes price. It has two scopes:

<ParamField query="scope" type="string" default="watch">
  `watch` or `removals`.
</ParamField>

| Scope | Who | Contents |
|---|---|---|
| `watch` | Any ticket | State and changes for the listing ids you send it |
| `removals` | Merchant ticket only | Every listing that leaves the market, in batches every 250 ms |

Use `watch` for a cart, a checkout page or an open listing view: send the
ids on screen, get their state back immediately, then get a push the moment
one of them sells or reprices. Use `removals` only if you serve the whole
book yourself and need to drop sold listings from it; expect around 9 MB/h
uncompressed, and enable `permessage-deflate` on your client.

## Authentication

The live socket uses the same JWT ticket as the [WebSocket](/guides/websocket)
event stream. Every ticket carries the `market` scope; a ticket minted by a
merchant for itself (no `On-Behalf-Of`) also carries `market:merchant`, which
unlocks `scope=removals` and a larger watch limit.

<Steps>
  <Step title="Mint a ticket">
    Call `POST /auth/ws-token` — with `On-Behalf-Of` for an end user's
    socket, without it for one your backend holds.

    ```ts
    const { token } = await api<{ token: string; expiresIn: string }>(
      "/auth/ws-token",
      { method: "POST" },
      "user_42",
    );
    ```
  </Step>
  <Step title="Open the socket">
    Pass the token as a `bearer.<jwt>` subprotocol (preferred — query
    strings leak into logs) or as `?token=`:

    ```ts
    const ws = new WebSocket(
      "wss://api.skinshark.gg/market/live?scope=watch",
      [`bearer.${token}`],
    );
    ```
  </Step>
  <Step title="Wait for the ready frame">
    ```json
    { "event": "market.ready", "data": { "scope": "watch", "limit": 500 }, "ts": 1714678920000 }
    ```

    `limit` is how many listing ids this socket may watch at once: 500 on an
    end-user ticket, 20,000 on a merchant ticket.
  </Step>
</Steps>

## Watching listings

Send ids as JSON text frames. A frame is at most 32 KB, so split a large
set into frames of a few hundred ids.

```json
{ "op": "watch", "ids": ["0190f4c2-…", "0190f4c3-…"] }
{ "op": "unwatch", "ids": ["0190f4c2-…"] }
```

Every `watch` frame is answered with the current state of each id in it,
including ids you already watched:

```json
{
  "event": "market.state",
  "data": {
    "listings": [
      { "listingId": "0190f4c2-…", "alive": true, "price": 12.48, "delivery": "instant" },
      { "listingId": "0190f4c3-…", "alive": false }
    ]
  },
  "ts": 1714678920000
}
```

`alive` is `false` when the listing sold, was delisted, is held by an
order already in flight, or would be refused by `POST /market/buy`. `price`
already includes the fee of the user the ticket was minted for.

After that, changes arrive as they happen:

```ts
type LiveEvent =
  | { event: "market.ready"; data: { scope: "watch" | "removals"; limit?: number }; ts: number }
  | { event: "market.state"; data: { listings: ListingState[] }; ts: number }
  | { event: "market.updated"; data: { listings: { listingId: string; price: number }[] }; ts: number }
  | { event: "market.removed"; data: { listings: { listingId: string; itemId?: string }[] }; ts: number }
  | { event: "market.error"; data: { key: "WATCH_LIMIT"; limit: number }; ts: number };

type ListingState = {
  listingId: string;
  alive: boolean;
  price?: number;
  delivery?: "standard" | "instant";
};
```

- `market.removed` — the listing is gone. A sale reaches you within about a
  second; anything else that makes a listing unbuyable within about 5 seconds.
- `market.updated` — the listing's price changed.
- `market.error` with `WATCH_LIMIT` — the frame would have taken the socket
  past its limit. Nothing in it was added; unwatch some ids and retry.

A malformed frame closes the socket with `4002 Bad frame`. On a
`removals` socket any frame closes it with `4002 Read-only`.

## Reconnecting

The socket has no replay. After a reconnect, send your whole watch set
again: the `market.state` answer tells you which listings died while you
were away, so nothing else is needed to catch up.

<Info>
  Prices are fixed to the fee tier at connect time. A fee change takes
  effect on the next reconnect.
</Info>

## Buying a listing that just sold

Even with the socket, a listing can sell between the user's click and the
purchase. `POST /market/buy` answers `404 LISTING_NOT_FOUND` with
`error.listingIds` naming exactly the dead ids, before any money moves. To
have the purchase take the next copy instead, send
`fallback: "same_item"` on the item: if the listing is gone by the time it
is bought, the cheapest other listing of the same item, phase and delivery
tier at or under your `maxPrice` is bought in its place.

## Close codes

| Code | Reason | Cause |
|---|---|---|
| 4001 | Missing token | No ticket in the subprotocol or `?token=` |
| 4001 | Invalid token | Bad signature, expired, or wrong purpose |
| 4002 | Bad frame | A `watch` socket got a frame that isn't a valid `watch`/`unwatch` |
| 4002 | Read-only | A `removals` socket got any frame |
| 4003 | Forbidden | Ticket lacks the `market` scope, or `scope=removals` on an end-user ticket |
| 4008 | Too many connections | Over the per-user socket limit |

A user may hold up to 5 concurrent live sockets. For the reconnect
pattern (mint a fresh ticket on `4001`, back off on network blips), see
the [WebSocket](/guides/websocket#reconnection) guide.
